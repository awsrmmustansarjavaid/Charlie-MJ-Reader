Compatibility Adapter Package Guide

JSON and ZIP adapters are local packages. Imported JavaScript is stored as data and is not automatically executed.

← Settings

ZIP package structure

medium-freedium/
├── adapter.json       REQUIRED
├── adapter.js         OPTIONAL (stored as data)
├── sources.json       OPTIONAL
├── README.md          OPTIONAL
└── assets/            OPTIONAL

Install flow

  1. Open Settings → Compatibility Adapters.
  2. Choose Import Adapter Package (.zip).
  3. The ZIP is checked for safe paths, size limits, supported compression, adapter.json, ID and semantic version.
  4. If an adapter with the same ID exists, confirm replacement.
  5. The complete package is stored under the logical extension path extensions/adapters/<id>/.
  6. Use Enable / Disable without deleting the package.

Validation rules

  • No absolute paths or .. traversal.
  • Maximum 500 entries; per-file and package size limits are enforced.
  • Only ZIP stored/deflate compression is accepted.
  • adapter.json is required.
  • id must be a safe package identifier.
  • version must look like 1.0.0.
  • If entry is declared, that file must exist.

Security model

The extension does not call eval(), new Function(), or inject imported adapter JavaScript as extension code. The package manager keeps the adapter files available for review and future host-controlled adapter operations.

Export / backup

Installed adapter metadata and files are part of the local extension data model and can be exported for backup. Chrome extensions cannot write arbitrary files into their own installed directory; the displayed extensions/adapters/ path is the extension's logical adapter storage namespace.

Example manifest

{
  "id": "medium-freedium",
  "name": "Medium / Freedium",
  "version": "1.0.0",
  "type": "compatibility",
  "entry": "adapter.js",
  "capabilities": ["detect", "reader", "metadata", "content", "images"]
}
